## Saved technical context

- Python >=3.11; audit ran on Windows 11 with Python 3.12.13. Dependencies:
  httpx, python-dotenv; sqlite3 from the standard library; pytest and Ruff for checks.
- Entrypoints: `uv run viralclip ...` and `uv run python -m viralclip ...`.
- Runtime files: `src/viralclip/cli.py`, `config.py`, `twitch/client.py`,
  `collector/service.py`, `storage/database.py`.
- Default database: `data/viralclip.sqlite3`; configurable with VIRALCLIP_DB_PATH
  or global `--db`. Never commit real databases, exports or secrets.
- Schema migration v2 adds job-to-snapshot linkage, retry timing and unique run
  counts. Existing measurements are not rewritten or deleted.
- Audit fixes preserve fetched pages after later failures, prevent checkpoints
  skipping incomplete split windows, detect near-cap saturation, validate malformed
  payloads, atomically complete snapshot jobs, lock out competing collectors,
  poll due snapshots between discovery cycles, validate OAuth tokens, and isolate
  category failures. See the audit for severity and test details.
- Several overdue jobs can link to one current observation after restart. Their
  target ages remain on jobs; the observation retains its actual age/time.
- No ML, UI, paid infrastructure, publishing, system settings changes or git push
  were performed. The audit changes were uncommitted when this handoff was written;
  inspect `git status` and preserve existing work before making changes.
