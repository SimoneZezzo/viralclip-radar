## 24. Che cosa costituisce prova

Un unit test isola per esempio `_retry_delay` e gli header. Un integration test fa interagire DB, collector, parser e client con un trasporto simulato. Una regressione fissa un difetto riproducibile, per esempio il primo exit 1 che troncava il controllo duale. “Offline” significa che la prova può girare senza parlare con i servizi reali. Si possono comunque usare SQLite, Bash, Git e processi Python reali con dati ed effetti confinati nell'area temporanea sintetica. Live significa osservare il comportamento reale in una finestra datata con un'origine identificata. Il recovery verifica la ripresa dopo perdita di processo o restore. L'integrity test controlla byte, chiavi e relazioni. La riproducibilità confronta input, output o digest contro regole dichiarate.

Verifica locale del 20 novembre su Windows. Il comando richiesto `uv run --offline --no-sync python -B scripts/verify_offline.py --strict` ha dato **7 PASS**. Pytest **159 passati**, zero errori e zero skip, Ruff lint/format PASS (34 file Python), Git PASS, sintassi Bash PASS (3 file), parser PowerShell PASS (36 blocchi/file) e packaging PASS (52 file da HEAD `c01480c6d401`). Sono stati usati soltanto SQLite e file temporanei sintetici durante i test, con trasporti simulati. La verifica non ha interrogato Twitch o le infrastrutture. ## 25. Limiti e debito tecnico

Impatto/urgenza si riferiscono alla milestone interessata. **Confermato** indica un comportamento osservabile nel sorgente o nelle prove esistenti. **Rischio** indica un effetto che va misurato. Il registro tiene distinti i difetti storici corretti e i limiti attuali.

| Priorità | Osservazione verificabile | Effetto e prova mancante |
| --- | --- | --- |
| Alta, prima del rollout | **Confermato da evidenza storica.** Le otto unità attese risultavano assenti nella finestra osservata. L'attuale revisione e le automazioni alternative sono UNKNOWN. | Operazioni automatiche e boot restore non dimostrati. Fase 0 prima dei cambiamenti. [Stato](11-CURRENT-STATUS.md) |
| Alta, prima di prune | **Confermato nel codice.** Restic usa host/tag uguali per giochi. Scope separato è una condizione operativa esterna al runner. | Due profili diretti accidentalmente allo stesso repository possono interferire con retention e selezione. La guardia identità protegge l'accettazione del restore. [Ops](../../src/viralclip/operations.py#L202) |
| Alta, preflight e avvio | **Confermato.** `status` e un secondo processo `collect` possono raggiungere apertura/PRAGMA/migrazione prima dell'OS lock. Due limiti concreti del recupero meritano attenzione durante lo studio. `storage.backup.validate` verifica i cinque target attesi e link coerenti, mentre le verifiche di fase 0 controllano anche relazione numerica fra date e target. Le due routine non garantiscono gli stessi invarianti. Inoltre `update_watermark` ammette l'upsert con il valore fornito, senza guardia di monotonicità SQL. Con orologio di sistema affidabile il flusso normale avanza. Un salto all'indietro richiede analisi e non ha una regressione specifica fra quelle identificate.
